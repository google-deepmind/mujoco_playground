# Tabletop V0: Sim-to-Real VLM Robot Manipulation Demo

> [!TIP]
> **Developer Blogpost**: For technical background, architecture details, and zero-shot sim-to-real deployment across SO-101 and i2rt YAM, see the companion blogpost: [Gemini 4 Argon for Robotics](https://developers.googleblog.com/gemini-4-argon-for-robotics).

This demo packages a robot-agnostic sim/real tabletop harness **written entirely by an agent** and provided as-is.

A core point of this demo is that `reaf-sim` underneath lets an agent build, test, and iterate rapidly in simulation—authoring the IK controller, primitive executor, camera calibration, and task suite—before deploying the exact same stack zero-shot onto real hardware (`--mode=sim` to `--mode=real`).

It enables an external vision-language model (VLM) to perceive scenes through a wrist camera and manipulate objects via high-level primitives, with variable stepping so episodes unroll quickly and responsively rather than waiting on expensive per-step model inference.

## How to Run the Demo

### 1. Start the Bridge Server

Start the environment bridge in simulation or on the real robot:

```bash
# In simulation (use mjpython with --viewer on macOS, or python on Linux)
uv run --default-index https://pypi.org/simple --extra so101 mjpython -m mujoco_playground.tasks.agentic.tabletop_v0.run --mode=sim --robot=so101 --task=cube_in_bowl --agent=bridge --viewer

# On real hardware
uv run --default-index https://pypi.org/simple --extra so101 python -m mujoco_playground.tasks.agentic.tabletop_v0.run --mode=real --robot=so101 --agent=bridge
```

### 2. Prompt Your Agent

Point your agent to [`AGENT_PROMPT.md`](AGENT_PROMPT.md) with your desired task:

> "Get the so101 to &lt;your task&gt; following `mujoco_playground/tasks/agentic/tabletop_v0/AGENT_PROMPT.md`"

## Supported Hardware

- **SO-101**: 5-DoF follower arm with monocular wrist camera (`--robot=so101`).
- **i2rt YAM**: 6-DoF follower arm with monocular wrist camera (`--robot=yam`).

Both robots are supported in both simulation (`--mode=sim`) and physical hardware (`--mode=real`).

## Adding New Hardware

To add new hardware, follow the existing robot implementations in [`robots/so101`](../../../robots/so101/) or [`robots/yam`](../../../robots/yam/) to provide:

1. An `MjSpec` scene with a `pinch` site centered between fingertips (z-axis pointing along fingers, x-axis along jaw closing direction) and a `wrist_cam`.
2. Follower device implementations in `sim/device.py` and `real/device.py`.
3. An `embodiment.Embodiment` entry registered in `tabletop_v0/embodiment.py`.

## Architectural Details

If you're interested in what the agent came up with under the hood:

At each turn, the robot bridge serves `obs.json` and an annotated wrist image (`wrist_cam.png`), and the VLM replies with a Python plan (`POST /plan`). Some key features:

- **FK Metric Overlay & Ray Deprojection**: Projects a 2 cm world-XY grid and `[ + ]` jaw reticle onto `wrist_cam.png` (plus a reference `calibration.png` on reset) so the VLM can command world `(x, y)` or image `(u, v)` coordinates.
- **50 Hz Code-as-Policies Primitives**: Compiles Python calls (`look_at`, `grasp`, `place`, `goto`, `move_by`, `move_until_contact`, `sweep`) into minimum-jerk 6-DoF trajectories solved by damped least-squares `PinchIK`.
- **Sensorless Contact & Slip Recovery**: Monitors pinch tracking lag and jaw aperture to stop on contact (`move_until_contact`) or, with `verify_grasp=True`, abort and reopen when the jaws close to their commanded opening (empty or slipped grasp, `status="grasp_failed"`).
- **Zero-Shot Sim-to-Real (`reaf-sim`)**: Runs the identical harness and IK stack across `--mode=sim` and `--mode=real` on SO-101 and i2rt YAM by swapping only the follower device layer.
